# Reviewed agent memory: local browser proof

On 2026-09-19, the Interface at `http://127.0.0.1:5176/opensaddle-interface/` was connected in Chrome to a disposable Core process at `http://127.0.0.1:8767`. The fixture ran `scripts/agent-setup-browser-fixture.py --reviewed-memory` against current Core code. It created a temporary Git Project, captured `README.md`, and completed the normal retained-evidence review route before the browser opened Agent Setup. The token and all content were test-only; the temporary directory disappears when the fixture stops.

The browser rendered one Core-advertised, unchecked memory source with its source ID, private classification, KRAIL ResourceRef identity, version, and `sha256:` digest. After selecting it and creating a proposal, the review panel showed the same pinned source plus both source and resource record digests before the publish control became available. [Review screenshot](../../out/screenshots/agent-memory-20260919/review.jpg).

The published agent's task form initially showed the reviewed source unchecked. Selecting it and starting the task admitted Run `run_56d69323233c450bbfb0b09b0f7823cc`; the page showed the canonical Run link. [Task selection screenshot](../../out/screenshots/agent-memory-20260919/task-selection.jpg) and [admission screenshot](../../out/screenshots/agent-memory-20260919/task-admitted.jpg).

A separate authenticated read of the real Core Inspector packet route for that Run returned `available: true`, Core binding to the same Run, packet digest `sha256:cb88a9e6540aeb405b3974e8444be2875d0e2901bb8061f1e6318cd83503efdd`, and the fixture note marker inside the packet. The marker's text is intentionally omitted here. This proves task admission and packet construction, not provider execution: no native worker was started for this browser fixture. Core's owning tests cover worker and Inspector packet identity plus withdrawal revocation.

During the browser pass, the initial Interface parser rejected a real KRAIL ResourceRef because it had incorrectly assumed the shape used by action proposals. The actual six-field `{authority, contract, digest, resource_id, resource_type, version}` shape is now used by the parser and tests. Visual inspection also caught a memory checkbox stretching across the form and a white-on-white hovered Start task button; both received local CSS fixes and the saved screenshots reflect the corrected layout.
